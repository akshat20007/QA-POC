# QA PoC — Known Issues

Tracks code-review findings for `qa-poc/` that are reported but not yet fixed, plus a log of what's already been resolved. Update this file whenever an open issue is fixed (move it to Resolved with the date and what changed) or a new review pass identifies something new (add it to Open with a fresh ID).

ID format: `KI-NNN`, assigned sequentially and never reused, even if an issue is later dropped as invalid.

## Open

| ID | Category | File | Summary | Failure scenario |
|---|---|---|---|---|
| KI-001 | correctness | `qa-poc/generate.py` (`ensure_login_precondition`) | Login-step injection can't express a story that intentionally wants a logged-out session — the heuristic only distinguishes "has its own login steps" from "needs one injected," with no third option. | A story like "verify an unauthenticated user is redirected to login when visiting /inventory.html directly" gets force-logged-in by the injected steps before its own steps run, inverting the test's actual intent. |
| KI-002 | correctness | `qa-poc/web/src/components/StepEditor.tsx` | Deleting the prepended login steps in the Review-stage UI has no safety net — they're ordinary editable/deletable steps with nothing marking them as structurally required, and `runner.ts` has no login-specific fallback. | A user deletes the 4 login steps from a non-login test case in Review and runs it; the test silently executes against an unauthenticated page instead of failing fast with a clear error. |
| KI-003 | reuse | `qa-poc/web/src/api/types.ts` | Every wire type is hand-copied from `qa-poc/executor/src/apiTypes.ts`/`types.ts` with no shared source or build-time link between the two npm packages. | A future payload-shape change on the server compiles cleanly on both sides independently; the mismatch only surfaces at runtime as an undefined field or silent misrender. |
| KI-004 | reuse | `qa-poc/web/src/components/ReportView.tsx` | Hand-rolls its own PASS/FAIL pill and step-row markup instead of reusing `Badge.tsx`'s `StatusBadge`/`StepOutcomeBadge` and `StepList.tsx`'s row rendering. | A future style/behavior change to the shared step-row/status-pill pattern gets applied to `StepList` but not to `ReportView`'s separate copy, so the Report stage silently drifts from the Execution stage's presentation of the same data. |
| KI-005 | simplification | `qa-poc/web/src/state/AppStateContext.tsx` (`START_RUN`/`RESUME_RUN`) | Both reducer cases duplicate the same `liveProgress`/`testOrder` scaffold-building loop; `testOrder` is also fully derivable from `Object.keys(liveProgress)` rather than needing separate state. | Adding a required field to `LiveTestProgress` means updating the same object literal in two places; forgetting one desyncs a fresh run from a resumed-after-refresh run. |
| KI-006 | simplification | `qa-poc/web/src/state/AppStateContext.tsx` (`HYDRATE` action) | Defined and handled in the reducer but never dispatched anywhere — dead code left over from an earlier persistence design (actual load path uses `useReducer`'s lazy-init argument). | A future contributor assumes `HYDRATE` is the live rehydration path, edits/debugs it, and is confused when persistence behavior doesn't change. |
| KI-007 | efficiency | `qa-poc/executor/src/runner.ts` (`runTestCases`) | Test cases run sequentially in a `for` loop even though each opens its own isolated `BrowserContext` against one shared browser, with no ordering dependency between them. | A run of 6 independent test cases takes ~6x a single test's duration instead of running with a small concurrency pool — pure wasted wall-clock time. |
| KI-008 | efficiency | `qa-poc/web/src/state/AppStateContext.tsx` (`AppStateProvider`) | One shared context with a freshly-allocated `{state, dispatch}` value re-renders every consumer on every dispatch, including every SSE `step-result` event during a run. | During a long run, every component calling `useAppState()` re-renders on every step event; combined with `ProgressView` having no memoized per-test card, every step event re-renders every test's card, not just the one that changed. |
| KI-009 | efficiency | `qa-poc/executor/src/store.ts` (`runs` map) | No delete/TTL/eviction path exists — every `RunState` (full `events[]`/`reports[]`) is retained for the life of the process. First flagged in an earlier review round; still unaddressed. | The dev server (`npm run server`/`server:dev`) left running across many generate/run cycles permanently grows memory with no way to reclaim it short of a restart. |

## Resolved

| ID | File | Summary | Resolved |
|---|---|---|---|
| KI-R01 | `qa-poc/executor/src/run.ts`, `qa-poc/generate.py` | `add_to_cart` would log in twice: `run.ts` hardcoded a `performValidLogin` precondition while `generate.py`'s new `ensure_login_precondition` also prepended login steps to the same test's JSON. | 2026-08-30 — removed the hardcoded precondition from `run.ts`; login is now handled solely by the JSON-level injection. |
| KI-R02 | `qa-poc/executor/src/translator.ts` (`classifyAction`) | `.includes('select')` matched the substring inside "selected," misclassifying assertions like "verify previously selected item stays visible" as select actions. | 2026-08-30 — switched to whole-word (`\b...\b`) matching via a `hasWord()` helper. |
| KI-R03 | `qa-poc/executor/src/server.ts`, `runner.ts` | A mid-run crash discarded every already-completed test's report, even though those results had already streamed to clients over SSE as passing. | 2026-08-30 — `runTestCases` now never rejects; it always resolves with whatever reports completed and emits exactly one terminal event. |
| KI-R04 | `qa-poc/executor/src/runner.ts` (`runOne`) | `browser.newContext()`/`newPage()` ran before the `try`/`finally` meant to guarantee cleanup, leaking the context if either call threw. | 2026-08-30 — moved context/page creation inside the `try`. |
| KI-R05 | `qa-poc/executor/src/server.ts` (SSE `/api/runs/:runId/events`) | Every reconnect replayed the entire event history from the start, ignoring the `Last-Event-ID` header `EventSource` sends automatically, producing duplicate steps in the UI. | 2026-08-30 — the handler now honors `Last-Event-ID` and skips already-delivered events. |
| KI-R06 | `qa-poc/web/src/api/client.ts` (`subscribeToRunEvents`) | No `onerror` handler on the `EventSource`, so a dead/unreachable run endpoint retried forever with nothing surfaced to the app. | 2026-08-30 — added `onerror`; refined same day to only treat it as fatal when `readyState === CLOSED`, so transient drops still auto-recover instead of being killed on the first blip. |
| KI-R07 | `qa-poc/web/src/pages/ExecutionStage.tsx` | Unhandled promise rejection if the post-`run-complete` report fetch failed — no user-visible error, no recovery. | 2026-08-30 — added `.catch()`, wired into a new `runError` state field with a visible "Run stopped" banner. |
| KI-R08 | `qa-poc/web/src/state/AppStateContext.tsx` (`APPLY_RUN_EVENT`) | The reducer had no case for the `'error'` event type, so a mid-run crash left the UI frozen on "running" forever with no way to recover short of a manual refresh. | 2026-08-30 — added an `'error'` case that sets `runError`, surfaced in `ExecutionStage`. |
| KI-R09 | `qa-poc/web/src/components/StepEditor.tsx`, `ReportView.tsx` | Two UI copy strings had gone stale: the Value field's "(fill steps only)" label (select steps need it too) and the "tool does not infer implicit setup steps" note (it now does, via `ensure_login_precondition`). | 2026-08-30 — both updated to match actual behavior. |
| KI-R10 | `qa-poc/generate.py` (`_has_own_login_steps`) | Required the literal substring "fill" in a step's action, but `translator.ts`'s `classifyAction` treats "enter" as an equivalent fill-type verb — a login test phrased "enter username" would be judged as having no login steps and get double-logged-in. | 2026-08-30 — `fills()` now checks for "fill" or "enter", matching `classifyAction`'s own vocabulary. |
| KI-R11 | `qa-poc/web/src/pages/ExecutionStage.tsx`, `ReportStage.tsx` | Fetched the run report immediately after the `'run-complete'` SSE event without checking `status`, racing a real (if short) gap between that event firing and the server actually marking the run complete — could show a false "0/0 success" screen. | 2026-08-30 — added `getCompletedRunReport()` (polls until `status: 'complete'`) in `client.ts`; both pages now use it. |
| KI-R12 | `qa-poc/web/src/App.tsx` | The mount-time reconciliation effect reset the *entire* session (stories, edited test cases) on any report-fetch failure, not just "the run no longer exists." | 2026-08-30 — added an `ApiError` class carrying the HTTP status; the reset now only fires on an actual 404. |
| KI-R13 | `qa-poc/executor/package.json` | `@types/express ^5.0.0` (devDependency) next to a runtime `express ^4.21.1` — a major-version type/runtime mismatch. | 2026-08-30 — pinned to `@types/express ^4.17.21`. |
| KI-R14 | `qa-poc/web/vite.config.js`, `vite.config.d.ts`, `tsconfig*.tsbuildinfo` | Stray compiled `tsc` output committed alongside the real `vite.config.ts` source. | 2026-08-30 — removed the files and added `*.tsbuildinfo` to `qa-poc/.gitignore`. |
